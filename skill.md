# Programming troubleshooting notes

- **Cross-realm test values:** Arrays/objects created inside Node `vm` have different prototypes; strict deep equality can fail despite identical contents. Normalize at the boundary (for example, `Array.from(vmArray)`) before asserting.
- **Keep quiz feedback safe:** Render generated element data with `textContent` and DOM nodes, not `innerHTML`; this avoids accidental HTML interpretation and keeps feedback accessible.
- **Random quiz coverage:** Shuffle a copied data array (`slice()` first) before selecting questions/options; avoid mutating the reference list so replay and study mode stay correct.
- **Android APK builds in GitHub Actions:** When Android SDK/Gradle are unavailable locally, use a checked-in Gradle project under `android/` and a workflow that provisions JDK 17, Android SDK command-line tools, the required platform/build-tools via `sdkmanager`, and Gradle. Build with `gradle --no-daemon -p android :app:assembleDebug` and upload `android/app/build/outputs/apk/debug/app-debug.apk` as a workflow artifact. Pin a maintained Ubuntu runner and current actions; this project's verified workflow uses Ubuntu 24.04, checkout v7, setup-java v6, setup-android v4, Gradle setup v6, and upload-artifact v7. Keep Java and Kotlin bytecode targets aligned (this project uses 17 for both), or `compileDebugKotlin` can fail with inconsistent JVM target compatibility. Run the Node integration check before pushing, but only a GitHub Actions run validates Android compilation when the local SDK is absent.
- **PWA vs. Android package warnings:** A PWA installed by Chrome is browser-managed and has no project APK `targetSdk`. Raising the native APK's `targetSdk` only affects that APK; it cannot directly change Play Protect or Android install warnings for a Chrome-installed PWA. Diagnose which app/package generated the warning before promising that a manifest change will resolve it.
